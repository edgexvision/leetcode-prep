How to Approach Any Coding Question

  1. Clarify (2 min): Ask about input size, edge cases (empty, negative, duplicates), and output format. Never start coding without this.
  2. Identify the pattern (1 min): What is this problem really asking? Is it a search? A frequency count? A path through a graph? Match it to a known pattern.
  3. State your approach out loud (2 min): Explain your plan in plain English before touching the keyboard. Name the pattern. State time and space complexity.
  4. Code from top to bottom (10-15 min): Write clean, named variables. Handle the main case first, then edge cases.
  5. Test with examples (3-5 min): Walk through your code with the given examples by hand. Then check: empty input, single element, all duplicates, negative numbers.
  6. Optimize if time allows: Can you improve time complexity? Space? Mention the trade-off even if you don't code it.

Edge Cases to Always Consider

Arrays
  • Empty array []
  • Single element [x]
  • All same elements [x,x,x]
  • Negative numbers
  • Already sorted
  • Reverse sorted
Strings
  • Empty string ""
  • Single character
  • All same characters
  • Unicode / spaces
  • Case sensitivity
Graphs / Trees
  • Empty graph / null root
  • Single node
  • Disconnected components
  • Cycles
  • Very deep tree (recursion limit)
Numbers
  • Zero
  • Negative numbers
  • Integer overflow (mention it)
  • k = 0 or k = n
  • target not achievable
